# Changelog

## 2.0.2

- Порт `80/tcp` больше не требуется и не публикуется на хосте для DEEBOT X1.
- Убран внешний bind legacy-портов `1883/tcp` и `5223/tcp`; они остаются доступны внутри Docker-сети Bumper.
- Минимальный набор host-портов X1: `443/tcp`, `8007/tcp`, `8883/tcp` (+ `8090/tcp`, только если включена отдельная PWA).
- Установщик генерирует `docker-compose.x1.yaml` из зафиксированного upstream Bumper Compose и отказывается продолжать, если структура upstream неожиданно изменилась.
- `update.sh` и `restore.sh` повторно генерируют X1-профиль, чтобы обновление Bumper не вернуло лишние публикации портов.

## 2.0.1

- Upstream Bumper по умолчанию зафиксирован на стабильном `v0.4.1`; повторный `install.sh` больше не обновляет его скрыто.
- `update.sh --latest` обновляет на последний стабильный GitHub release с предварительным backup; `--ref` позволяет выбрать ревизию явно.
- PWA получила CSRF-защиту для управляющих POST-команд и серверную проверку, что комнаты действительно сопоставлены этому vacuum entity.
- Dashboard-контейнер запускается непривилегированным пользователем.
- Добавлены CI, unit-тесты, issue templates, документация архитектуры/диагностики и правила безопасной разработки.

## 2.0.0

- Home Assistant полностью отделён от установщика Bumper.
- Добавлены режимы `external`, `export`, `none`.
- Порт 8123 больше не резервируется и не проверяется как конфликт.
- Backup/restore/update/uninstall не управляют Home Assistant.
- Добавлены `configure-ha.sh`, `export-ha-config.sh`, `ha-check.sh`.
- Export никогда не пишет `.storage` и не патчит `configuration.yaml`.
- Отдельная PWA стала опциональной и умеет подключаться к удалённому HA.
- Добавлена поддержка self-signed HA TLS через явный `--insecure-ha`.
- PWA показывает только HA Areas, реально сопоставленные сегментам vacuum entity.
- Добавлены примеры reverse proxy для Nginx/Caddy.
